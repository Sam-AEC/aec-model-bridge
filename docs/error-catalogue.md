# Error catalogue

Errors and refusals that the AEC Model Bridge server returns to clients, with what to do about each.
This file is generated by `scripts/make_error_catalogue.py` from the source and from
`scripts/error_catalogue_notes.json`. Do not edit it by hand.

A tool failure reaches an MCP client in one of two shapes:

- The MCP layer refused or failed the call. The reply has `isError: true` and `structuredContent.error.kind` is a tool error kind.
- A module tool ran and returned `ok: false` with a result kind in `kind`, a `message` and a `hint`.

Refusals never change the model. A refused write needs a new plan that a person approves.
For logs and connection problems see [troubleshooting](troubleshooting.md).

Entries: 137.

## Tool error kinds

Set by the MCP layer as `structuredContent.error.kind` when a call fails with `isError`. Entries: 8.

### `approval_blocked`

- When: The approval gate refused a call that changes the model: no approved plan, a plan that does not match, an expired approval, a policy rule, or a changed document.
- What to do: Read the message. Create a plan with plan_actions, ask the person to approve it, then run it with execute_plan. Do not retry the same call unchanged.
- Source: `packages/mcp-server-revit/src/revit_mcp_server/mcp_server.py`

### `bridge_error`

- When: The server could not reach Revit, lost the reply, or Revit ran the command and it failed.
- What to do: Run revit_health. Check that Revit is open with the add-in and a project loaded. After a failed write, read the attached result before planning again.
- Source: `packages/mcp-server-revit/src/revit_mcp_server/mcp_server.py`

### `execution_error`

- When: A tool raised an error that is not one of the kinds above, for example bad arguments or a file problem.
- What to do: Read the message and fix the arguments. If it repeats with valid arguments, report a bug with the log (docs/troubleshooting.md).
- Source: `packages/mcp-server-revit/src/revit_mcp_server/mcp_server.py`

### `human_only`

- When: An AI client called approve_plan, reject_plan or rollback_plan.
- What to do: Stop. Ask the person to approve, reject or roll back the plan in the Revit panel or with the aec-model-bridge-approve command.
- Source: `packages/mcp-server-revit/src/revit_mcp_server/mcp_server.py`

### `invalid_response_options`

- When: The response_options argument is not an object, names an unsupported key, or has a value of the wrong type.
- What to do: Remove response_options or fix it as the message says, then call again.
- Source: `packages/mcp-server-revit/src/revit_mcp_server/mcp_server.py`

### `task_not_supported`

- When: A tools/call carried a task field (MCP Tasks) for a tool that does not accept task-augmented calls. Nothing ran and no approved action was used.
- What to do: Call the tool without the task field, or use a tool whose execution.taskSupport is optional (docs/mcp-tasks.md).
- Source: `packages/mcp-server-revit/src/revit_mcp_server/mcp_server.py`

### `tool_profile_blocked`

- When: The tool is registered but this server's static MCP tool profile hides it.
- What to do: Use a tool the profile lists. To use this one, the person must change the tool profile and restart the server (docs/mcp-token-budget.md).
- Source: `packages/mcp-server-revit/src/revit_mcp_server/mcp_server.py`

### `unknown_tool`

- When: The tool name is not registered in this server.
- What to do: Call tools/list and use an exact name. A module tool is missing when its module is off or failed to load.
- Source: `packages/mcp-server-revit/src/revit_mcp_server/mcp_server.py`

- What to do: Use a path inside the workspace (revit_get_context shows it). Do not try to reach other folders.
- Source: `packages/mcp-server-revit/src/revit_mcp_server/errors.py`
