# ADR 0023: MCP specification 2026-07-28 and Python SDK 2.x

## Status

Proposed. Spike only (issue #271, tracking #269). The `mcp` dependency stays at `>=1.30.0,<2` and default behaviour does not change.

## Context

The server speaks MCP over stdio through the low-level `mcp.server.Server` class of the Python SDK 1.x line. The installed SDK is `mcp` 1.30.0. Its newest protocol version is `2025-11-25`, and it accepts `2024-11-05`, `2025-03-26`, `2025-06-18` and `2025-11-25` in the `initialize` handshake.

MCP specification `2026-07-28` changes the core protocol:

- The core is stateless. The `initialize` / `notifications/initialized` handshake is removed. Each request carries its protocol version and client capabilities in `_meta` (`io.modelcontextprotocol/protocolVersion`, `io.modelcontextprotocol/clientCapabilities`). A version mismatch returns `UnsupportedProtocolVersionError`.
- Servers must implement `server/discover`, which returns supported versions, capabilities and identity.
- Server-initiated requests (`roots/list`, `sampling/createMessage`, `elicitation/create`) are replaced by multi round-trip requests: the server returns `resultType: "input_required"` and the client retries with the answers. Every result carries `resultType`.
- `ping`, `logging/setLevel` and `notifications/roots/list_changed` are removed. Log level is set per request in `_meta`; a server must not send `notifications/message` for a request that did not ask for it.
- `resources/subscribe` and the HTTP GET stream are replaced by `subscriptions/listen`. List-changed notifications travel only on that stream.
- `tools/list` should return tools in a deterministic order. List and read results carry `ttlMs` and `cacheScope`.
- Tasks leave the core and become the `io.modelcontextprotocol/tasks` extension. MCP Apps is the `io.modelcontextprotocol/ui` extension. Extensions are negotiated through a new `extensions` capability field.
- Deprecated, with removal no earlier than the first revision released on or after 2027-07-28: Roots, Sampling, Logging and OAuth Dynamic Client Registration. The HTTP+SSE transport is reclassified as Deprecated.
- On stdio, a client that supports both eras sends `server/discover` first. Any error that is not a recognised modern error, or no answer, means the server is legacy and the client falls back to `initialize`. A legacy-only client cannot talk to a modern-only server.

The Python SDK 2.x line implements `2026-07-28` and negotiates back to every earlier revision. `mcp` 2.0.0 was tagged on 2026-07-28; later tags are 2.1.0, 2.2.0 and 2.3.0. The 1.x line (`v1.x` branch, latest 1.30.0) receives critical and security fixes only. The SDK 2.x Tasks extension is not implemented yet. SDK 2.x requires Python 3.10 or later at tag 2.3.0 (3.11 on `main`). The comment in `pyproject.toml` that says 2.x needs Python 3.12 does not match these tags.

## MCP features this server uses

`tests/test_mcp_spec_2026_07.py` builds this inventory from the source code (imports, attribute names, call keywords and MCP method strings under `src/`). It fails when a feature appears that this table does not name.

| Feature id | Where | Status in 2026-07-28 |
| --- | --- | --- |
| `tools` | `mcp_server.py` (`list_tools`, `call_tool`); `providers/proxy.py` as a client | Active. Deterministic order recommended; `ttlMs`/`cacheScope` on `tools/list`. |
| `tool_annotations` | `tool_metadata.py`; `providers/proxy.py` reads upstream hints. `providers/tool_search.py` reads them from tool dicts and does not import the SDK, so the scan does not list it. | Active. |
| `structured_output` | `mcp_server.py` (`structuredContent` on error results) | Active. Schemas and `structuredContent` loosened to any JSON Schema 2020-12 value. |
| `server_instructions` | `mcp_server.py` (`SERVER_INSTRUCTIONS`) | Active. Returned by `server/discover` for modern clients. |
| `prompts` | `mcp_server.py`, `mcp_prompts.py` | Active. |
| `resources` | `mcp_server.py`, `mcp_resources.py` (list, templates, read) | Active. Resource-not-found error code changes from `-32002` to `-32602`. |
| `http_sse_transport` | `providers/proxy.py` (`sse_client`, used when `MCP_PROXY_TARGETS` is set) | Deprecated. Migrate to Streamable HTTP. |

Not used: Logging (`notifications/message`, `logging/setLevel`), Roots, Sampling, Elicitation, Completions, progress notifications, resource subscriptions, list-changed notifications, Tasks, MCP Apps. Python logging goes to stderr and the audit log, which is the migration path the specification names for Logging. The server advertises `tools`, `prompts` and `resources` capabilities, each with `listChanged: false` and `subscribe: false`.

The panel hub (`panel_server.py`) is a loopback HTTP shim with its own token and Host/Origin checks. It does not speak MCP and is not affected by the specification. The VS Code extension starts the stdio server and is not affected.

## Protocol version negotiation today

The spike tests drive the server with the SDK in-memory streams:

- `initialize` with each handshake version the installed SDK supports returns that version.
- `initialize` offering `2026-07-28` returns `2025-11-25`, the newest version the server knows. A dual-era client then stays on the handshake.
- `server/discover` sent before `initialize` returns JSON-RPC error `-32602` at once, which is not a modern error code. A dual-era stdio client treats the server as legacy and falls back to `initialize`, which still succeeds on the same connection.

So today the server is a legacy server that dual-era clients can use. A client that only speaks `2026-07-28` cannot use it. The installed SDK does not negotiate `2026-07-28`, so no test checks a modern request yet.

## Spike result: `mcp` 2.3.0

The full suite was run once with `uv run --with "mcp==2.3.0" pytest -n 4`, without changing `pyproject.toml` or `uv.lock`: 3,570 passed, 34 failed, 15 skipped, 96 errors. The failures fall into three groups:

1. Import failure. `mcp_server.py` uses the `@app.list_tools()` style decorators, which SDK 2.x removed (handlers are now `on_*` constructor arguments). Every test that imports `mcp_server` fails at collection (17 files, 4 workers each), and so do the stdio smoke test, `--help`/`--version`, `doctor` routing and the tool-count script.
2. Field names. SDK 2.x uses snake_case model fields (`read_only_hint`, not `readOnlyHint`). `tool_metadata.py`, `providers/tool_search.py` and the annotation audit read the camelCase attributes and fail.
3. Proxy approval rule. `is_proxied_tool_read_only` reads `annotations.destructiveHint` and `readOnlyHint` with `getattr`. Under SDK 2.x both return `None`, so an upstream tool named `get_*` with `readOnlyHint: false` or `destructiveHint: true` is treated as read-only and skips the approval gate. Two cases of `test_proxy_read_only_rule` in `tests/test_ungated_tools_gated.py` catch this. It must be fixed before any 2.x release; it is the reason the upgrade cannot be a pin change.

## Decision

Stay on SDK 1.x for release 1.6. Move to SDK 2.x as its own change set after 1.6, in the steps below. Do not adopt deprecated features. Keep the approval gate unchanged: `plan_actions`, human approval and `execute_plan` work the same in both eras, because approval never depended on sampling, elicitation or server-initiated requests.

## Migration plan

Each step is one pull request with its own tests. Steps 1 to 3 work on SDK 1.x and make the upgrade smaller.

1. Read annotations through one helper that accepts both camelCase and snake_case names, and use it in `proxy.py`, `tool_search.py` and `tool_metadata.py`. Add a test that a destructive `get_*` upstream tool stays gated with both field spellings.
2. Return tools from `tools/list` in a fixed order and test it.
3. Move the handler bodies in `mcp_server.py` into plain functions that return full result objects (`ListToolsResult`, `CallToolResult`, `ReadResourceResult`, and so on). The decorators become thin wrappers. This matches the SDK 2.x rule that handlers return complete results.
4. Raise the dependency to `mcp>=2.3,<3` and register handlers as `on_*` constructor arguments. Port camelCase fields to snake_case. Fix the in-memory and stdio tests. Add the dual-version test: `initialize` with `2025-11-25` and a modern request with `2026-07-28` in `_meta` both succeed, and `server/discover` returns `2026-07-28` in its supported versions.
5. Check the resource-not-found error code (`-32602`) and add `ttlMs`/`cacheScope` if the SDK does not fill them in.
6. Replace `sse_client` in `providers/proxy.py` with the Streamable HTTP client, keep the fail-closed approval rule, and remove the allowlist entry. The legacy HTTP+SSE path can stay behind an explicit setting for one release if a user needs it.
7. Run the client checks in the table below and update it. Mark results as observed only where a person ran them.

Tasks and MCP Apps stay out of scope. Long-running work already uses `run_async` and job ids returned as tool results, which is the handle pattern the stateless core recommends. Any new transport, including Streamable HTTP for the server itself, needs the same token, loopback and Host/Origin checks as the panel hub.

## Risks

- Proxy approval rule fails open after a plain dependency bump (spike group 3). Step 1 removes it.
- Legacy-only clients cannot reach a modern-only server. SDK 2.x keeps the handshake path, so the server stays dual-era; a test must hold that.
- The in-process SDK 2.x `Client` negotiates `2026-07-28` by default. Tests that assume the handshake must pin `mode="legacy"` or use a low-level `ClientSession`.
- Notifications are dropped on modern connections unless the request opts in. The server sends none today.
- SDK 2.x raises dependency floors and replaces `httpx` with `httpx2`. Check the lock file, the wheel smoke test and the third-party notices.
- Client support for `2026-07-28` is not confirmed for any client below.

## Consequences

The inventory test keeps this ADR and the code in step. A new use of Logging, Roots, Sampling or HTTP+SSE fails CI until it is added to the allowlist here with a reason. The SDK upgrade becomes a planned change with a known failure list instead of a surprise at import time.
