# Changelog

## Unreleased

- `aec-model-bridge-approve` review: `show` and `approve` print, per action, a table of element (id, plus name and Mark from the plan's snapshot when it can be read), parameter and old -> new value, then counts, warnings (review, preview, expiry, malformed), the short plan hash, approval mode, expiry and document binding. Plain text with no ANSI by default; `--color` colors it only on a terminal that supports it with `NO_COLOR` unset. Long values wrap; more than 30 rows end with a "+N more ..., use --all" line, and `approve` refuses a plan whose review was cut short until it is run with `--all`. New `--show PLAN_ID` (review only, same as `show`), `--all` (every row, full values) and `show --json` (machine-readable review, schema `aec-model-bridge/plan-review` version 1). Approval still needs the typed plan id, and `--yes` remains the only way to approve without a terminal.
- New read-only tool `revit_perf_report`: per-command timings from the add-in's `/health` (`count`, `p50_ms`, `p95_ms`, `max_ms`, `avg_bytes`) as a table sorted by p95, plus `queue_depth`. An add-in without `timings` is reported as older; mock mode returns sample numbers marked `mock: true`. Revit area: 111 tools.
- Faster cold start in mock mode: spawn to `tools/list` reply 825 ms to 575 ms. `openpyxl`/`numpy` and `yaml` load on first use, the Speckle and Autodesk Data providers build their HTTP clients on first request, and the module registry reads the package version once. Numbers in `docs/performance.md`.

- Add-in timings (#285): each request records `queued_ms`, `run_ms`, `serialize_ms` and response bytes in the `Request completed` log line, and `/health` reports `timings` per tool (`count`, `p50_ms`, `p95_ms`, `max_ms`, `avg_bytes` of run time over the last 200 runs). Only read-mode scripts share the engine; a write-mode script always gets a new one. The reset runs at the end of each read-mode script inside its read guard, so a callback a script leaves behind cannot change the model outside the guard. Read-mode guards are unchanged. UNVERIFIED in live Revit.

- Read results cut by the size cap now carry an opaque `cursor`; the same call with `response_options.cursor` returns the next part from server memory without running the tool again (#274). Cursors are bound to the tool, arguments and `fields`, last `MCP_REVIT_READ_CURSOR_TTL` seconds (default 600) and are refused with kind `invalid_cursor` when expired or mismatched. `MCP_REVIT_READ_MAX_CHARS` sets the server-wide cap. A cut list too large to keep in memory is saved under `<workspace>/results/` and linked as `aec://result/<id>` (#283). See `docs/read-cursors.md`. UNVERIFIED against a live Revit.

## 1.5.1 - 2026-11-24

- Security: the workspace policy is now re-checked when any approved action is claimed, so a direct tool call carrying `plan_id` can no longer run an action a tightened (or invalid) policy prohibits. Before, only `execute_plan` re-checked it.
- Excel import keeps cell text exactly, so an unedited value with leading or trailing spaces is no longer planned as a change; whitespace-only cells count as blank.
- Binding probe reuse with `max_age_s=0` now always probes again; on Windows' coarse monotonic clock two reads in the same tick were treated as fresh.
- `doctor` no longer flags a virtual environment's own `Scripts\python.exe` as a #159 launcher.
- CI: a `changes` job skips the add-in and Rhino builds on pull requests that do not touch C#; pull requests run Python on Windows 3.11 and Ubuntu 3.13, while pushes to `main`/`dev`, a nightly run and manual runs keep the full matrix (Ubuntu is no longer experimental). Installs use `uv sync --locked` with a cache, tests run in parallel (`pytest-xdist`), and the coverage floor rises from 55% to 80% (measured 83%).
- `ids` extra pins `ifcopenshell` below 0.9: `ifctester` 0.8.x cannot read 0.9 entities.
- README first screen rewritten: headline "The Revit MCP server that asks first", a three-step picture (`assets/readme-flow.svg`: AI proposes, you approve, Revit changes), a one-line pre-release status with the detail kept under "Status and limits", and the compatibility paragraphs moved above Star History. Headings are unchanged. A test now checks the tool count stated under the headline.
- Agent tooling: a Sonnet `issue-fixer` subagent; shared `.claude/settings.json` that allows the test/lint commands and blocks reads of very large generated files. `.gitignore` now tracks `.claude/agents`, `.claude/skills` and `.claude/settings.json` only.
