## 1.5.0 - 2026-11-16

- Read-only tool results are now minified JSON by default (about 14-24% fewer characters on typical reads; pass `response_options.compact: false` for indented text) and capped at 20,000 characters. Over the cap, the largest lists are trimmed to valid JSON and marked `truncated: true` with `total`, `returned` and a hint to narrow the call; `response_options.max_chars` changes the cap (0 turns it off). Plans, proofs, approvals, jobs, errors and every tool that can write are untouched.
- `revit_list_elements`, `revit_list_views`, `revit_list_families`, `revit_get_categories`, `revit_get_warnings` and `revit_get_schedule_data` accept optional `limit`, `offset` and `count_only`. The slice is made in the server after Revit answers (no add-in change), so it saves response tokens, not Revit time.
- MCP tool text is shorter and clearer: the duplicate `annotations.title` is gone, repeated parameter text (`dry_run`, `on_error`, `limit`, `tag`, `fields`, `status_labels`) uses one short wording, and 29 look-alike tools say which sibling to use for what. About 3.5% fewer tokens in the full and daily catalogues; approval wording is unchanged.
- Tool profiles can no longer hide the approval tools (`plan_actions`, `execute_plan`, `list_pending_plans`, `plan_revert`, `get_proof_bundle`). A custom profile file that excludes the approval provider is refused with a clear error.
- Dev mode wording: the server instructions, panel chat prompt and `plan_actions` description now say that when `revit_get_context` shows `server.dev_mode` true, write tools are called directly with no plan or `plan_id`. In Dev, `plan_actions` still creates the plan but adds `dev_mode: true` and a note. A supplied plan that is still pending is refused as before, with a clearer message. Approval rules are unchanged.
- `aec-model-bridge-approve reject --older-than DAYS` and `--all-pending` (with `--dry-run`) clear out old pending plans. They touch pending plans only and print each id; approved and executed plans are left alone.
- Plan-shaped results are never compacted or trimmed, including `parameter_manager_plan_set_params`, `revit_mep_hanger_plan`, `revit_recipe_get` and any result with `plan_type` or `plan_arguments`. Paging arguments reject `inf`/`nan` and read `count_only: "false"` as false; `count_only: false` alone no longer applies a default limit. `aec-model-bridge-approve reject --older-than` refuses `nan`, `inf` and negative values. Module handlers declared as `def h(*args)` again receive the arguments dict.
- `/diagnostics` now reports `workspace_dir` and a `dev_off_reason` when Dev reads off (for example a key or workspace mismatch). It never includes the token or nonce.

- Require `certifi>=2026.10.19` and refresh its lock entry so the release bundle cannot restore the affected emSign trust root (GHSA-6q48-6c7w-9gw2). Regression checks cover the dependency floor and the actual bundled trust store.

- Audited the 19 open PRs from oldest to newest and consolidated their current implementations and fixes. Setup recovery supports Codex-only chat; previews clear stale state and accept 64-bit IDs; QA issues are isolated by rule pack; explicit workspace allowlists are preserved. Snapshot audits disclose partial data and no longer invent full-model findings from incomplete captures. Snapshot point locations use SI units and stable names survive serialization. See `docs/release-audit-2026-11-06.md` for coverage and remaining live acceptance work.
- MCP token use: static `full` (default), `daily` and custom module profiles; hidden direct/plan/job targets are refused without weakening approval. Optional compact/read-field responses and `plan_actions` argument-echo omission reduce returned text while retaining full human-review data in storage. Measurements and reproduction commands are in `docs/mcp-token-budget.md`.
- Release preparation: restore patched MCP/Speckle/GraphQL and VS Code packaging dependencies, regenerate complete third-party notices, install portable runtime dependencies from the lock and validate the release SBOM against its actual installed distributions. Correct extension release dispatch, provenance checks, checksums, support routes and setup documentation. No live model writes were used for these checks.

- Ribbon: new "cut slate" icons, matching the Recipe Editor tab. They come in light and dark variants and are embedded in the DLL, and the old vector icons stay as a fallback.
